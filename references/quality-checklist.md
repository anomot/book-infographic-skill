# QA Checklist (Reader Advocate)

Read the rendered PNG as a phone reader. Any failure = veto, rework, re-render.

## Content

- [ ] The five universal questions are answered somewhere in the piece (not necessarily as five columns).
- [ ] Every headline readable in ~3 seconds; no sentence a casual reader can't parse on first pass.
- [ ] Nothing true-but-useless survived. Every block earns its space.
- [ ] Facts (author bio, dates, numbers, quotes) traceable to source; nothing invented.

## Design

- [ ] Theme, structure, and the one amplified conclusion recognizable in ~3 seconds on a phone.
- [ ] Structure differs from other books in the same batch.
- [ ] Every graphic carries information; at most one decorative illustration, and it earns its place.
- [ ] Max 3 main colors + paper tone; no all-centered / all-card / gradient-everywhere styling.
- [ ] Headers in natural spoken language, not template boilerplate.
- [ ] Whitespace ~30%+; clear typographic hierarchy; one visual motif throughout.

## Technical

- [ ] No clipped text, no overflow, no mojibake at 2x render.
- [ ] 1080px width; readable at phone scale.

## Multi-image consistency (only in multi-image mode)

- [ ] One shared visual language: same palette, motif, and type scale across all pages.
- [ ] The overview does only "the thesis + the map"; it is not a shrunken full version of the book.
- [ ] Every module page names its own question and could stand alone.
- [ ] Module numbers match between the overview map and the module page headers.
- [ ] Each page's layout pattern fits that page's information relationship (patterns may differ across pages).
- [ ] The set reads as one book, not N posters.
